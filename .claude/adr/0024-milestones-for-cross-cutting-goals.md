# ADR-0024: 여러 이슈에 걸친 목표는 GitHub 마일스톤으로 묶는다

- 상태: Accepted
- 관련: [ADR-0016](0016-track-in-github-not-docs.md)(추적은 문서가 아니라 GitHub 으로 — 이 ADR 은 그 결정을 뒤집지 않고 보강한다), [ADR-0019](0019-remove-frozen-roadmap.md), [ADR-0020](0020-generate-release-notes-from-prs.md), [rules/github.md](../rules/github.md)

## 배경 (Context)

[ADR-0016](0016-track-in-github-not-docs.md)이 추적을 문서에서 GitHub 으로 옮긴 뒤, 로드맵의 단일
소스는 Project #4 "SQL Server Farm 로드맵" 이다. 지금까지 이 저장소의 로드맵 항목은 대체로
**항목 하나 = 이슈 하나 = PR 하나**였다. 그런 항목에는 Project 의 Status 열만으로 충분했고,
그래서 [rules/github.md](../rules/github.md) 는 현황으로 "마일스톤은 쓰지 않는다(0건)" 이라고
적어 두었다.

**크로스 플랫폼 지원**에서 그 전제가 처음 깨졌다. "Windows · macOS · Linux 에서 똑같이 돌게
한다" 는 목표는 셸 런타임(PowerShell 5.1 ↔ pwsh 7) · 경로 처리 · 바인드 마운트 권한 ·
Docker 런타임 · 인코딩 규약([ADR-0012](0012-utf8-bom-for-powershell.md)) · CI 3-OS 매트릭스 · 문서 문구로
쪼개진다. 각 조각은 저마다 이슈와 PR 이 되지만, **완료 기준은 하나**다 — 세 OS 에서
`check.ps1 -Test` 가 통과하고 `start` → `status` → `backup` 기본 경로가 동작하는 것.

Project 로는 이 관계를 표현하기 어렵다. Project 는 **항목 하나하나의 상태**를 담는 도구라,
"이 일곱 개가 사실은 한 목표이고 지금 3/7 왔다" 는 정보를 담으려면 커스텀 필드를 하나 더
만들어 손으로 채워야 한다. 그런데 그 묶음은 GitHub 이 이슈 자체에 **이미 기본 제공**하는 축
(마일스톤)이다. 필드를 새로 만드는 쪽이 오히려 중복이다.

## 결정 (Decision)

**여러 이슈가 모여야 끝나는 하나의 목표는 GitHub 마일스톤으로 묶는다.** 첫 사례는
[마일스톤 #1 "크로스 플랫폼 지원 (Windows · macOS · Linux)"](https://github.com/Chigo55/Docker-Compose/milestone/1) 이다.

- **마일스톤 설명에 `범위` 와 `완료 기준` 을 적는다.** 완료 기준은 마일스톤 한 곳에만 두고,
  소속 이슈가 저마다 복사하지 않는다. 마일스톤은 그 기준을 만족했을 때 닫는다.
- **Project #4 와는 축이 다르다. 서로 대체가 아니다.**

  | | Project #4 | 마일스톤 |
  |---|---|---|
  | 담는 것 | **항목 단위 상태** — Status · Priority · Effort · Type | **공통 완료 기준을 공유하는 이슈 묶음**의 진척률(N/M) |
  | 답하는 질문 | "이 항목은 지금 어디까지 왔나" | "이 목표는 몇 개 남았나" |
  | 단일 소스 | **로드맵 전체**([ADR-0016](0016-track-in-github-not-docs.md)) | 묶음의 완료 기준 |

  **로드맵의 단일 소스는 여전히 Project 다.** 마일스톤은 로드맵을 대체하지 않으며, 이슈
  하나가 Project 항목이면서 동시에 마일스톤 소속일 수 있다. 대신 **같은 정보를 양쪽에 적지
  않는다** — 상태는 Project 에, 묶음과 완료 기준은 마일스톤에.
- **마일스톤을 만들지 않는 경우.**
  - **단일 이슈로 끝나는 일.** 이슈 하나짜리 마일스톤은 진척률이 0/1 → 1/1 뿐이라 아무것도
    더 알려주지 않는다.
  - **완료 기준 없는 주제 묶음**(예: "문서 개선"). 끝이 정의되지 않으면 닫을 수 없어 영구히
    열려 있는 목록이 된다. 그런 분류는 **라벨**이 한다.
  - **릴리스 버전 묶음.** 릴리스 노트는 병합된 PR 의 라벨에서 자동 생성한다
    ([ADR-0020](0020-generate-release-notes-from-prs.md)). 마일스톤을 `v1.2.0` 같은 버전 통으로 쓰면 그 자동 생성과
    이중 관리가 된다.
- **마일스톤을 새로 열거나 닫으면 [rules/github.md](../rules/github.md) 의 현황도 같이 고친다.**
  그 문서는 원격 설정의 현황 기록이라, 안 고치면 설정이 단일 소스가 되고 다음 사람은 UI 를
  뒤져야 한다([ADR-0016](0016-track-in-github-not-docs.md)).

## 결과 (Consequences)

- **좋은 점**: 여러 이슈에 흩어진 하나의 목표를 진척률 한 줄(N/M)로 본다. 이슈 목록에서
  `milestone:` 로 걸러 남은 일만 볼 수도 있다.
- **좋은 점**: 완료 기준이 한 곳에 있어 이슈마다 복사되지 않는다. 개별 이슈를 열었을 때
  "이게 왜 필요한가" 의 답이 마일스톤 링크 하나 거리에 있다.
- **좋은 점**: GitHub 기본 기능이라 Project 커스텀 필드를 늘리지 않는다.
- **감수할 점**: 추적 축이 둘(Project · 마일스톤)로 늘어, 이슈를 만들 때 설정할 곳이 하나
  더 생긴다. [ADR-0016](0016-track-in-github-not-docs.md)이 없앤 삼중 관리로 되돌아갈 위험은 **역할 구분을
  지키는 것**으로만 막힌다 — 위 표의 경계를 넘어 같은 정보를 양쪽에 적기 시작하면 이 결정을
  다시 봐야 한다.
- **감수할 점**: 마일스톤은 저장소 단위, Project 는 계정 단위라 두 화면을 오간다.
- **감수할 점**: [rules/github.md](../rules/github.md) 에 갱신 대상이 하나 는다. 그래서 그 문서에는
  **개수를 세지 않고** 쓰는 기준과 열려 있는 마일스톤만 적는다 — "0건" 같은 숫자를 적었다가
  실제와 어긋났던 것이 이 ADR 을 쓰게 된 계기다.
